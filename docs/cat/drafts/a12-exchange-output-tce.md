## 反例と未決部分
- [PR #444](https://github.com/surumeneco/SimpleCoins/pull/444)で、正規両替と同一IDのSTONE出力への実レジストリ置換をPaperが受理し、現行実装の`CoinExchangeRecipes.isApproved`が正規貨幣の投入を許可した。これはp2/c2/a2側の拒否条件候補に該当するが、イベント完全実行ではなくガードの呼出し検査。
- 上記条件で`入力.正規両替レシピ`と`入力.登録済み出力一致`が独立した観測なのか、入力に抽象化して十分なのかは、人間の設計確認とCAT正式閉包を必要とする。
- 他Pluginによる監視後・クリック後のresult変更、Shiftでの複数確定、最終的な通常仕訳は本Draftの状態空間に含めず、未決の関連Processまたは本Processへの追加仕様候補とする。**これらを未対応なのに閉包済みと判定してはいけない。**
