# Phase 6 整合スナップショット・復旧の受入検証

## 適用境界

SimpleCoins 1.0.0の起動時全件決算・仕訳・発行予約・障害復旧について、**実行すべき故障注入と成功判定**を固定する検証計画。仕様の新規決定や実機検証済み宣言ではない。

- 設計正本：[02B_データ収集・決算処理](https://drive.google.com/file/d/1eczGiqZgCNevfGhIJCkS2B1acvRRP0P8/view) の起動時/停止時決算、データ静止条件、世代一括切替、仕訳と異常時の未公開。
- TaskQueue：`TASK-20261101-005`（整合スナップショット・仕訳・障害復旧）。子タスクの完了だけでSimpleCoins 1.0.0のリリース可否を決定しない。
- 関連実装：`DurableFile.java`（`develop`、保存プリミティブ）、[GrantLedger候補PR #10](https://github.com/surumeneco/SimpleCoins/pull/10)（Draft）。[リンク境界の検証](phase6-durable-link-boundary.md)は別資料に保持し、ここで重複記載しない。
- CATのConfirmed、Process/PI/TCE機械Gate、Paper実機試験、二重書込防止の決定は別々の証拠を必要とする。

## 実行の前提

対象コミットSHA・JARハッシュ・Paper/Java版・ワールド/プラグイン構成・保存先・決算世代を記録する。本番データではなく、コピーした独立の検証環境で実施する。故障注入前に復元可能なバックアップを作成し、外部公開・配布・統計表示を無効化する。時刻、投入貨幣額、UUID、保存場所、再起動回数、注入位置、ログ、観測した世代を証拠にする。

## 判定と引渡し

1. 各ベクトルを`passed / failed / inconclusive / not-run`で記録し、**対象HEAD、故障位置、実行コマンド、実ログ、再起動後の正本値**を紐付ける。単体テストのGreenをPaper実機成功としない。
2. `RC-06`は切替点の前後を個別に検証する。ファイルのatomic move成功だけでは、複数ファイル/DB/メモリの**世代全体**の原子性を証明しない。
3. `RC-07〜10`は予約ジャーナルの検査であり、全件決算の世代切替と別の契約。個々の成功を他方へ流用しない。
4. 一つでも必須ソースが未読取・不確定、または復旧の一回性が未実証なら、決算・統計の全件成功を公開しない。現行実装の`not-run`は`passed`に変換しない。

現時点で本書のベクトルは**検証計画**であり、CAT Gate、Paper実機、クラッシュ後の全件決算成功は未実施である。Draft Redテスト（例：非末尾予約欠損、リンク境界）は修正済みの証拠ではない。
